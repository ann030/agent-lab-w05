CORE OBJECTIVES

核心目標：培養 AI 協作的四大關鍵判斷力

PLAN
1. 看懂計畫
  • 在 AI 動手前審查白話計畫
  • 確認輸入與輸出路徑
  • 辨認破壞性或越權操作
VERIFY
2. 檢查成果
  • 使用客觀指標（如 Hash 雜湊）
  • 逐項執行驗收測試案例
  • 比對檔案副本與原檔一致性
BOUNDARY
3. 辨認權限
  • 嚴守最小權限與工作區隔離
  • 原始資料一律保持唯讀
  • 未經授權絕不外連或公開
REJECT
4. 退回做法
  • 發現高風險指令時果斷拒絕
  • 精準指出問題核心
  • 提供安全合規的替代方案
TASK A · 01-CLUB-FILES

社團檔案安全整理與盤點

安全準則
整理原則與原檔保護
  • 原檔絕對不動： input/ 12 個文字檔保持唯讀，不刪除、不覆蓋。
  • 拒絕盲信檔名： proposal_final 與 proposal_final2 內容完全不同（室外 vs 室內），皆標註未定案，不可自行刪除。
  • 安全複製至 proposals, meetings, logistics, promotion 四大目錄。
驗收成果
雜湊驗收與結構化產出
  • MD5 雜湊比對： 精準抓出完全相同的兩組檔案（announcement 與 equipment），全數保留副本。
  • 結構化清單： 產出 output/manifest.json（最外層 12 筆物件陣列，記錄 source, destination, reason）。
  • 盤點報告： 產出 output/report.md 詳列重複檔案與待決策問題。
  • Git Commit： A: organize club files
TASK B · 02-CAMPUS-PICKER

課間活動挑選器：單頁應用與 v1 到 v2 迭代

v1 基礎功能
純前端單頁離線應用
  • 零外部依賴： 內嵌 12 筆活動資料，無 CDN、無網路請求，雙擊即可開啟。
  • 多條件嚴格篩選： 地點（室內/室外/不限）、可用時間（15/30/60m）、強度（低/中/不限）。
  • 不放寬條件： 無符合活動時顯示「沒有符合條件的活動」，堅持原則。
  • 最近 5 筆歷史（最新在前）、重設篩選、中英雙語切換。
  • Git Commit： B v1: activity picker
v2 體驗升級
新增鍵盤快捷鍵支援
  • 現況 (v1)： 僅能點擊滑鼠按鈕抽卡，連續測試或手持鍵盤不便。
  • 改進 (v2)： 按鍵盤 Space（空白鍵）或 Enter 直接觸發隨機挑選！
  • 微動態回饋： 按鈕微縮動態與畫面多語系快捷鍵提示。
  • 防呆機制： 展開下拉選單時自動忽略，不干擾原生瀏覽器操作。
  • Git Commit： B v2: add Space and Enter shortcuts...
TASK C · 03-EQUIPMENT

社團器材記錄清理：數據正規化與異常保留

資料清洗
清洗與正規化規則
  • 文字欄位去除前後贅餘空白；qty 欄位不套用去空白規則，嚴格保留原值。
  • 狀態值標準化：可借/可出借/available 統一為 available；借出統一為 borrowed。
  • 非標準狀態（如第 9 列「待盤點」）標記為 unknown。
  • 整列全空才可移除：10 列原始資料正規化為 9 列有效（第 6 列移除）。
客觀存證
異常值保留與品質報告
  • 保留異常： 缺漏數量（qty: ""）與負數（qty: -1）原樣保留，不擅自補 0 或取絕對值。
  • 保留衝突： 相同 ID（EQ01, EQ02）全部保留，指出來源列號與數量衝突（2 vs 3）。
  • 產出 normalized.json 與 issues.md。
  • Git Commit： C: clean equipment records
TASK D · 04-REVIEW

安全防線：審查刻意寫錯的模擬計畫 (bad-plan.txt)

問題診斷
圈出 5 大高風險違規動作
  • ❌ 整理 Downloads 全部： 越權掃描個人隱私目錄 ➔ 限縮於工作資料夾。
  • ❌ 擅自刪除重複檔： 破壞不可逆 ➔ 原檔唯讀，保留副本供人工審查。
  • ❌ final2 當最新版： 盲目認定 ➔ 完整保留不同版本並列出差異。
  • ❌ 找不到補合理值： 數據偽造 ➔ 異常值原樣保留呈報。
  • ❌ 自動公開成果： 敏感資料外洩 ➔ 成果留存本地 output。
退回範本
撰寫正式退回指令 (my-rejection.md)
  • 產出正式審查文檔：practice/04-review/my-rejection.md。
  • 向 Agent 傳達明確指令：「這份計畫有多項不符規範，請停止並重新修正：限制工作目錄、原檔唯讀、不以 final 判定、異常原樣保留、成果僅存本地。重新提出白話計畫，確認後才可執行。」
  • Git Commit： D: rejection

KEY TAKEAWAYS
結語：負責任的 AI 協作心態
  • 人是核心決策者： 權限邊界、安全審核與業務邏輯決定權在人。
  • AI 是高效率副駕駛： 擅長大量分類、比對、清洗與生成，但需明確指示。
  • 凡事皆有憑據： 透過 Git Commit 與學習紀錄留存客觀數據與軌跡。
  • 安全與合規第一： 拒絕黑盒操作，堅持看懂白話計畫才放行。
